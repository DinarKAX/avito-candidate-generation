# Авито: кандидатогенерация для поиска услуг

Задача: для каждого поискового запроса вернуть до 50 объявлений из корпуса (189 212 шт.)
так, чтобы в них попали объявления, которые пользователь в итоге выбрал. Метрика — Recall@50.

## Результаты на локальной валидации

| Конфигурация | Recall@50 (V) |
|---|---|
| BM25 только по заголовку | 0.32 |
| BM25 по заголовку, без учёта локации → + приоритет локации | 0.32 → 0.65 |
| BM25 по заголовку + параметрам + описанию + локация | 0.81 |
| + пул кандидатов и ранкер CatBoost (без эмбеддингов, R = 3000) | 0.877 |
| + генератор со слабой локацией, дообученный e5-small (пул + признаки), R = 20000 | **0.929** |

Потолок полноты пула (доля правильных ответов, попавших хотя бы в ~524 кандидата):
0.923 без эмбеддингов → 0.940 с генератором со слабой локацией → 0.965 с эмбеддингами.

## Как запустить

Нужен Python 3.12 (проверено на macOS, Apple M3, 16 ГБ). Внешние API не используются:
веса open-source модели один раз скачиваются с HuggingFace, дальше всё работает локально.

```bash
uv venv --python 3.12 .venv          # или python3.12 -m venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

# файлы train.parquet, benchmark_items.parquet, benchmark_queries.parquet — в корне репозитория
.venv/bin/python src/prepare.py               # сплиты + лемматизация корпуса → cache/      (~4 мин)
.venv/bin/python src/train_dense.py train     # дообучение e5-small → models/e5-avito     (~1.5 ч)
.venv/bin/python src/train_dense.py encode    # эмбеддинги корпуса и запросов → cache/   (~40 мин)
EMB=e5ft .venv/bin/python src/run.py val      # оценка Recall@50 на локальной валидации
EMB=e5ft .venv/bin/python src/run.py final    # answer.csv
```

Все случайности зафиксированы (`SEED = 42`), поэтому повторный запуск даёт тот же `answer.csv`.

## Структура

| Файл | Что делает |
|---|---|
| `src/common.py` | загрузка, нормализация и лемматизация текста, сплиты train, метрика |
| `src/prepare.py` | шаг 1: сплиты H/R/V, «вселенная» объявлений, токены |
| `src/retrieval.py` | BM25 на scipy.sparse, локационный приоритет, top-k |
| `src/dense.py` | тексты для эмбеддингов, загрузка модели, кодирование |
| `src/train_dense.py` | шаг 2: дообучение e5-small и кодирование |
| `src/features.py` | ядро: пул кандидатов и признаки для ранкера |
| `src/run.py` | шаг 3: пулы → CatBoost → оценка или answer.csv (с проверкой формата) |
| `src/exp_*.py` | эксперименты, по результатам которых выбирались параметры |

## Подход

### 1. Валидация, похожая на бенчмарк

Семь попыток — слишком мало, чтобы подбирать решение по лидерборду, поэтому сначала
строилась локальная копия бенчмарка.

Наблюдение из EDA: запросы бенчмарка выбраны **равномерно по уникальным текстам**. Из них
37% встречаются в train, и они длиннее среднего, то есть это «хвост». Если брать для
валидации случайные *события* train, текст повторялся бы в 87% случаев, и всё, что опирается
на историю, выглядело бы гораздо лучше, чем есть. Поэтому train делится по событиям
(запрос + локация + фильтры) так:

- **V** — 2500 уникальных текстов, по одному событию на текст (доля повторяющихся 38.7%,
  как в бенчмарке 37%). Валидация.
- **R** — 20 000 уникальных текстов, так же. Обучение ранкера.
- **H** — всё остальное. Статистики и обучение эмбеддингов.

Для V и R признаки считаются **только по H**. Правильные ответы V/R подмешиваются
к корпусу бенчмарка, так что они соревнуются с теми же 189k объявлений.

### 2. Данные и признаки

- **Локация — главный сигнал.** 83% выбранных объявлений находятся в той же локации, что
  и поиск. Остальные — в соседних городах или это поиск по региону или всей стране
  (у 17% запросов бенчмарка в их локации нет ни одного объявления). Поэтому вместо
  жёсткого фильтра используется выученное по H распределение P(локация объявления |
  локация поиска) как мягкий приоритет, плюс расстояние в км до центра локации поиска.
  Одно это поднимает BM25 с 0.32 до 0.65.
- **Текст**: BM25 отдельно по заголовку, «полезной» части параметров (вид, тип, названия
  услуг; адреса, цены и расписания вырезаются) и началу описания. Слова лемматизируются
  (pymorphy3), ё → е.
- **Семантика**: `intfloat/multilingual-e5-small`, дообученный на парах «запрос →
  выбранное объявление» из H (MultipleNegativesRankingLoss, in-batch negatives).
  Ловит синонимы и перефразировки.
- **Рубрикатор**: P(подкатегория объявления | запрос) по истории H: смесь распределения
  по точному тексту (если встречался) и по отдельным словам. Точное совпадение
  «Вида услуги» из фильтра запроса с «Видом услуги» объявления. Доля слов фильтра,
  найденных в параметрах объявления. Фильтр по рейтингу.
- **Объявление**: рейтинг, число отзывов, цена, длина описания, флаги контактов.

Сознательно **не** используются идентификаторы объявлений и их популярность в train:
среди правильных ответов валидации 40% встречались в train, а среди объявлений корпуса
бенчмарка — только 9.6%. Такой признак был бы сильным на валидации и обманчивым на
бенчмарке. Пары «тот же текст запроса → то же объявление» повторяются лишь в 3.7% случаев,
поэтому история используется только в обобщённом виде (локации, подкатегории).

### 3. Алгоритм

1. По всему корпусу считаются BM25, косинус эмбеддингов, приоритет локации и
   P(подкатегория).
2. **Пул** (~524 кандидата) = объединение топов четырёх генераторов: BM25 + локация (300),
   BM25 + ослабленная локация (200), эмбеддинги + локация (200), BM25 + локация +
   подкатегория (100). Генераторы ошибаются
   по-разному, и объединение поднимает потолок полноты.
3. **Ранкер** CatBoost (Logloss) по ~30 признакам выбирает из пула топ-50. Для Recall@50
   порядок внутри топа не важен, поэтому поточечной классификации достаточно;
   YetiRank был в 15 раз медленнее.

### 4. Найденные ошибки и что с ними сделано

- **Утечка через порядок строк.** В первой версии добавленные в корпус правильные
  ответы стояли в конце массива. При равных значениях признака сортировка сохраняла
  порядок индексов, и ранкер выучил правило «большой индекс ⇒ правильный ответ»:
  Recall@50 0.888 вместо честных 0.877. Заметили по аномальной важности признака
  `dense_rank` в прогоне без эмбеддингов. Исправлено перемешиванием корпуса и случайным
  разбиением ничьих.
- **Проверка на вторую утечку**: не отличаются ли объявления из train от объявлений
  корпуса бенчмарка по данным (разные выгрузки)? Классификатор различает их с AUC 0.60,
  то есть различие слабое и объясняется популярностью. Признаки объявления оставлены.
- **Жёсткий фильтр по локации** терял 25% правильных ответов (в хвостовых запросах чаще
  ищут в соседних городах или по региону), поэтому он заменён мягким приоритетом.
- **Промахи пула** (разбор ошибок на V без эмбеддингов): 7.5% правильных ответов не
  попадали в пул, и 76% из них — в другой локации при хорошем совпадении текста
  («ремонт стиральных машин красногорск» → «Ремонт стиральных… машин» в соседнем городе).
  Добавлен генератор BM25 с ослабленным весом локации: потолок пула 0.923 → 0.940.
  Вторая группа — синонимы и опечатки («волитель на день» → «Трезвый водитель»,
  «шарики» → «Шары воздушные»); её закрывает дообученная модель эмбеддингов.
- **Невоспроизводимость между запусками.** Два одинаковых финальных прогона дали
  разные `answer.csv` (совпадение 96.5%). Причина: в `History.mc_dist` веса слов
  суммировались в цикле по `set(...)`, а порядок обхода множества строк зависит от
  случайного хэш-сида Python. Разный порядок сложения float давал разные последние биты
  признака `mc_logp`, дальше менялось обучение CatBoost. Нашёл, сравнив хэши всех
  признаков при `PYTHONHASHSEED=1` и `2`: отличались ровно `mc_logp` и `q_mc_entropy`.
  Исправлено обходом в отсортированном порядке.
- **Медленное обучение эмбеддингов**: `SentenceTransformerTrainer` на MPS работал
  ~49 с/шаг из-за накладных расходов сэмплера; замена на явный цикл с тем же лоссом дала
  ~6 с/шаг.
- **Шум в параметрах объявлений**: расписания, цены, адреса и «Рабочие дни Понедельник…»
  совпадали со словами запросов. Такие фрагменты вырезаются перед индексацией.

## Использованные open-source компоненты

- `intfloat/multilingual-e5-small` (MIT): базовая модель эмбеддингов;
- sentence-transformers, PyTorch: дообучение и кодирование;
- CatBoost: ранкер;
- pymorphy3: лемматизация;
- pandas, numpy, scipy, scikit-learn.
